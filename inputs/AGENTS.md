# AGENTS.md — 랜덤 발표자 뽑기## 프로젝트 개요초등학교 교사가 수업 중 사용할 수 있는 랜덤 발표자 뽑기 웹앱.학생 이름을 등록하고 버튼을 누르면 등록된 학생 중 한 명을 무작위로 선택해 화면에 크게 보여준다.서버 없이 `index.html`을 브라우저에서 더블클릭해 실행하는 프론트엔드 전용 앱이다.GitHub Pages에 그대로 업로드해 배포할 수 있어야 한다.사용자는 코딩을 모르는 교사이므로, 결과는 항상 브라우저에서 바로 확인할 수 있어야 한다.## 실행·확인 방법- 실행: `index.html`을 Chrome에서 연다. 빌드·설치·서버 실행은 없다.- 확인: 작업 후 `index.html`을 열어 학생 추가 → 학생 삭제 → 발표자 뽑기 → 전체 초기화가 정상 작동하는지 직접 확인한다.- 콘솔(F12)에 오류가 없는지 확인한다.- 문법 검사가 필요하면 `node --check script.js`만 사용한다. (node가 없으면 생략)## 기술 범위- HTML, CSS, JavaScript(ES2015+) 순수 파일만 사용한다.- 외부 라이브러리, CDN, npm, 빌드 도구, 프레임워크, 서버, 백엔드 API를 사용하지 않는다.- React, Vue, TypeScript 등을 사용하지 않는다.- 웹폰트·아이콘도 외부 로드 없이 시스템 폰트와 이모지·유니코드로 해결한다.- GitHub Pages에서 별도 설정 없이 실행될 수 있어야 한다.## 파일 구조 (이 구조를 유지)```textindex.html   화면 구조. 인라인 <script>·<style> 금지style.css    모든 스타일script.js    앱 로직```- 새 파일이 필요하면 만들기 전에 이유를 설명하고 사용자에게 확인한다.- CSS와 JavaScript는 반드시 별도 파일로 유지한다.- 파일 연결은 상대 경로를 사용한다.## 핵심 기능### 학생 관리- 학생 이름을 입력할 수 있다.- `추가` 버튼을 누르면 학생 목록에 추가한다.- Enter 키를 눌러도 학생을 추가할 수 있다.- 빈 이름은 추가하지 않는다.- 등록된 학생을 목록으로 보여준다.- 각 학생을 개별 삭제할 수 있다.### 랜덤 발표자 선택- `발표자 뽑기` 버튼을 제공한다.- 등록된 학생 중 한 명을 무작위로 선택한다.- 선택된 학생 이름을 화면에서 매우 크게 표시한다.- 학생이 한 명도 없으면 오류 대신 안내 메시지를 보여준다.### 전체 초기화- `전체 초기화` 버튼을 제공한다.- 학생 목록과 현재 발표자 결과를 모두 초기화한다.- 초기화 전 확인창을 표시한다.## 코딩 규칙- UI 문구는 모두 한국어로 쓴다.- 변수·함수 이름은 영어 camelCase를 사용한다.- `script.js` 파일 상단에 `'use strict';`를 사용한다.- DOM 조작은 `script.js`에서만 한다.- `index.html`에 `onclick=` 같은 인라인 이벤트를 쓰지 않는다.- 같은 기능이라면 더 짧고 이해하기 쉬운 코드를 우선한다.- 불필요한 클래스, 모듈, 추상화 구조를 만들지 않는다.- 주요 로직에는 코딩 초보 교사가 이해할 수 있는 짧은 한국어 주석을 작성한다.- 사용자가 요청하지 않은 기능을 임의로 추가하지 않는다.## 디자인 규칙- 밝고 현대적인 초등학교 교실 분위기로 만든다.- 흰색과 밝은 파란색 계열을 기본으로 사용한다.- 전자칠판에서 사용하기 쉽도록 버튼과 글씨를 크게 만든다.- 버튼 높이는 최소 48px 이상으로 한다.- 선택된 학생 이름은 교실 뒤에서도 읽을 수 있을 정도로 크게 표시한다.- 지나치게 화려한 효과나 복잡한 애니메이션은 사용하지 않는다.- 화면 너비 360px에서도 깨지지 않게 한다.- PC, 태블릿, 스마트폰에서 모두 사용할 수 있게 반응형으로 만든다.## 데이터·상태- 학생 목록은 JavaScript 배열로 관리한다.- 새로고침 시 학생 목록이 사라져도 괜찮다.- `localStorage`는 사용자가 요청할 때만 사용한다.- 데이터베이스나 외부 서버를 사용하지 않는다.## 개인정보·보안- 이 앱은 GitHub Pages에 공개 배포될 수 있음을 전제로 한다.- 학생 이름 외의 개인정보는 저장하지 않는다.- 학번, 전화번호, 주소, 계정 정보 등을 코드에 넣지 않는다.- API Key, 비밀번호, 토큰 등 비밀 정보를 HTML이나 JavaScript에 넣지 않는다.- 외부 API는 사용자가 명시적으로 요청하기 전까지 사용하지 않는다.## 수정 원칙- 사용자가 수정 요청을 하면 전체 프로젝트를 다시 작성하지 말고 필요한 부분만 수정한다.- 기존에 잘 동작하는 구조는 최대한 유지한다.- 디자인 변경 요청이면 먼저 CSS 수정으로 해결할 수 있는지 확인한다.- 기능 변경 요청이면 관련 JavaScript만 최소 범위로 수정한다.- 수정 후 기존 기능이 깨지지 않았는지 함께 확인한다.## 오류 처리- 오류가 발생하면 먼저 원인을 확인한다.- 오류 메시지가 있으면 해당 메시지를 기준으로 원인을 찾는다.- 문제와 관계없는 코드를 임의로 변경하지 않는다.- 수정 후 같은 오류가 다시 발생하는지 확인한다.- 오류를 숨기기 위한 임시방편보다 원인을 해결하는 것을 우선한다.## 경계✅ 항상 한다- 수정 후 `index.html`을 열어 주요 기능을 직접 확인한다.- 학생 추가 → 삭제 → 발표자 뽑기 → 전체 초기화 흐름을 확인한다.- 브라우저 콘솔에 오류가 없는지 확인한다.- PC 화면과 좁은 모바일 화면에서 레이아웃이 깨지지 않는지 확인한다.- 기존에 동작하던 기능이 그대로 동작하는지 함께 확인한다.- 작업이 끝나면 바꾼 파일과 내용을 3줄 이내로 요약한다.⚠️ 먼저 묻는다- 파일을 추가·삭제하거나 파일 구조를 바꿀 때- 외부 라이브러리나 API를 사용하려 할 때- `localStorage` 등 브라우저 저장 기능을 추가할 때- 학생 데이터 구조를 크게 변경할 때- 기존 핵심 기능을 삭제하거나 동작 방식을 크게 바꿀 때🚫 하지 않는다- 외부 라이브러리·CDN·패키지 설치- React, Vue, npm 등 별도 빌드 환경 추가- 서버·백엔드·데이터베이스 코드 추가- 프로젝트 폴더 밖의 파일 읽기·수정- 사용자가 요청하지 않은 기능 추가- 개인정보나 API Key를 코드에 저장- 동작하는 전체 코드를 이유 없이 다시 작성## GitHub Pages 배포 기준- `index.html`이 프로젝트 루트에 있어야 한다.- `style.css`, `script.js`는 상대 경로로 연결한다.- 로컬 PC의 절대 경로를 사용하지 않는다.- 서버 기능에 의존하지 않는다.- GitHub 저장소에 파일을 그대로 올렸을 때 동작해야 한다.예:```html<link rel="stylesheet" href="./style.css"><script src="./script.js" defer></script>```## 완료 기준- 콘솔 오류 0개- 학생 이름을 추가할 수 있다.- Enter 키로 학생을 추가할 수 있다.- 학생을 개별 삭제할 수 있다.- 발표자 뽑기 버튼을 누르면 등록된 학생 중 한 명이 선택된다.- 선택된 학생 이름이 화면에 크게 표시된다.- 학생이 없을 때 적절한 안내가 나온다.- 전체 초기화가 정상 동작한다.- 모바일 화면에서도 레이아웃이 깨지지 않는다.- GitHub Pages에서 실행 가능한 구조를 유지한다.- 위 항목을 직접 확인한 뒤에만 "완료"라고 보고한다.
